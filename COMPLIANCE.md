## 1. Главный вывод — что делать

**Простого чекбокса «мне есть 18» — недостаточно.** Большинство законов 2025–2026 года прямо запрещают self-declaration (самодекларацию) как единственный метод проверки возраста.

### Что нужно добавить при регистрации:

1. **Поле даты рождения** (день / месяц / год) — обязательное.
2. **Поле страны** — для определения применимого закона.
3. **Логика на бэкенде:**
   - Рассчитать возраст из даты рождения.
   - Сравнить с порогом для страны пользователя.
   - Если ниже порога → заблокировать регистрацию **ИЛИ** запросить согласие родителя.
4. **Дату рождения сразу после проверки удалить** — хранить только возрастную группу (`under13`, `13-15`, `16-17`, `18+`).
5. **При регистрации через Google / Facebook / Apple** — дополнительно запросить дату рождения, если провайдер её не передаёт.

## 3. США — COPPA

### Закон
- **Children's Online Privacy Protection Act**, 16 CFR Part 312.
- Крупное обновление вступает в силу **22 апреля 2026**.
- Распространяется на сайты/приложения, направленные на детей до 13 лет **ИЛИ** имеющие фактическое знание о пользователях до 13 лет.

### Что можно
- Собирать дату рождения **только для проверки возраста** без согласия родителя, при условии:
  - Данные используются **только** для определения возраста.
  - Данные **удаляются сразу** после проверки.
  - Данные **не передаются** третьим лицам.

### Что нельзя (если пользователь < 13)
- Собирать **любые персональные данные** без верифицированного согласия родителя (VPC).
- Использовать данные детей для профилирования, рекламы, трекинга.
- Хранить данные дольше, чем необходимо.
- С 2026: передавать данные детей третьим лицам без **отдельного** согласия.

### Штрафы
| Нарушение | Штраф |
|---|---|
| Каждое нарушение (за ребёнка, за день) | **до $53 088** |
| Пример: 1000 детей × 30 дней | **~$1.6 миллиарда** |

### Решение для нашей соцсети
- При регистрации: собрать дату рождения → рассчитать возраст.
- Если < 13 → **отказать в регистрации** (самый простой и безопасный путь).
- Удалить дату рождения сразу после расчёта.
- Если в будущем захотим допустить детей — реализовать полный VPC-поток (см. раздел 17).

## 4. ЕС — GDPR + Digital Services Act

### Закон
- **GDPR Article 8**: по умолчанию возраст цифрового согласия = 16, но страны-участники могут снизить до 13.
- **Digital Services Act (DSA) Article 28**: платформы обязаны принимать «соразмерные» меры для защиты несовершеннолетних; таргетированная реклама для детей запрещена.
- **Европарламент (ноябрь 2025)**: голосование за единый порог 16 лет для соцсетей без согласия родителя.

### Что нужно сделать
1. Собирать дату рождения + страну при регистрации.
2. Определить национальный порог (см. таблицу выше).
3. Если возраст < порога → потребовать согласие родителя **ИЛИ** заблокировать.
4. Данные для проверки возраста минимизировать и не перепрофилировать.

### Штрафы
| Нарушение | Штраф |
|---|---|
| GDPR | **до €20 млн или 4% мирового оборота** (что больше) |
| DSA | **до 6% мирового оборота** |

### Решение
- Дата рождения + страна → определение возрастной группы → хранить только группу.
- Для пользователей между `minAge` и `consentAge` → поток согласия родителя (email-подтверждение).
- Для пользователей < 13 → блок.

## 5. Великобритания — Online Safety Act

### Закон
- **Online Safety Act 2023**, применяется с июля 2025.
- Регулятор: **Ofcom**.
- Возраст цифрового согласия: **13** (UK GDPR).

### Ключевые требования
1. **«Высокоэффективная» проверка возраста** — простая самодекларация (ввести дату, поставить галочку) **НЕ достаточна** по рекомендациям Ofcom.
2. **Допустимые методы**: проверка по документу (паспорт), оценка возраста по лицу, Open Banking, проверка через мобильного оператора, кредитная карта, цифровая идентификация.
3. **Недопустимые методы**: самодекларация, дебетовая карта без проверки возраста, просто предупреждение.
4. Ежегодная **оценка рисков для детей** — обязательна.

### Штрафы
| Нарушение | Штраф |
|---|---|
| Несоблюдение требований Ofcom | **до 10% мирового дохода** или блокировка сервиса |

### Решение
- Дата рождения как начальный гейт.
- Для пользователей из UK: **дополнительно** интегрировать стороннего провайдера верификации (Yoti, OneID, AgeChecked) для enhanced verification.
- Или: проверка через мобильного оператора (Vodafone/O2/Three/EE Age Verification API).

## 6. Австралия — запрет до 16 лет

### Закон
- **Online Safety Amendment (Social Media Minimum Age) Act 2024**.
- Действует с **10 декабря 2025**.
- **Жёсткий запрет** на соцсети для лиц до 16 лет. Родители **НЕ могут** дать согласие.

### Ключевые требования
1. Платформа должна принять «разумные меры» для предотвращения доступа лиц до 16.
2. Простая самодекларация — **недостаточна**.
3. Допустимые методы: проверка документа, биометрическая оценка возраста.

### Штрафы
| Нарушение | Штраф |
|---|---|
| Невыполнение требований | **до AUD $49.5 миллионов** (~$32 млн USD) |

### Решение
- Для австралийских пользователей: дата рождения → если < 16 → **полный блок, без вариантов**.
- Рассмотреть интеграцию со сторонним сервисом оценки возраста (facial age estimation).
- Никакого потока «согласие родителя» — закон его не допускает.

## 7. Китай — многоуровневая система

### Закон
- **Положение о защите несовершеннолетних в киберпространстве** (2024+).
- Обязательная **регистрация по реальному имени** (через национальный ID).

### Требования по возрастным группам
| Возраст | Правило |
|---|---|
| < 8 лет | **Фактический запрет** на большинство платформ |
| 8–14 лет | Строгие лимиты по времени, контенту; обязательно согласие родителя |
| 14–18 лет | Умеренные ограничения, доступен родительский контроль |
| 18+ | Без ограничений |

### Решение
- Для китайских пользователей: верификация через национальный ID (или делегировать партнёру).
- < 8 → блок.
- 8–14 → привязка к аккаунту родителя.
- 14–18 → ограниченный режим.

## 8. Южная Корея — PIPA

### Закон
- **Personal Information Protection Act (PIPA)** + Закон о содействии использованию IT-сетей.

### Ключевые требования
1. Пользователи < 14 → обязательное **верифицированное согласие родителя** (обычно через i-PIN или мобильную верификацию).
2. Строгая проверка возраста для доступа к контенту с ограничениями.

### Штрафы
- Значительные штрафы + административные санкции (конкретные суммы зависят от масштаба нарушения).

### Решение
- Дата рождения → если < 14 → блок или i-PIN верификация родителя.

## 9. Бразилия — Digital ECA

### Закон
- **Estatuto da Criança e do Adolescente Digital (Цифровой ECA)**.
- Вступил в силу **17 марта 2026**.
- Один из самых строгих законов в мире.

### Ключевые требования
1. **Обязательная проверка возраста** — самодекларация запрещена.
2. Аккаунты пользователей < 16 → обязательно **привязаны к опекуну**, который получает отчёты об использовании.
3. Родительский контроль и максимальная защита — **по умолчанию**.
4. **Запрет** таргетированной рекламы для несовершеннолетних.
5. **Запрет** лутбоксов в играх.

### Штрафы
| Нарушение | Штраф |
|---|---|
| Невыполнение | **до 10% дохода в Бразилии**, приостановка сервиса, полный запрет |

### Решение
- Дата рождения → если < 16 → привязка к аккаунту опекуна или блок.
- Рассмотреть проверку через ID для бразильских пользователей.

## 10. Канада — PIPEDA

### Закон
- **Personal Information Protection and Electronic Documents Act (PIPEDA)**.
- Обсуждается новый законопроект о запрете соцсетей для < 14.

### Текущие требования
- Платформы обычно устанавливают порог 13+ (как в COPPA).
- Усиление контроля ожидается в ближайшее время.

### Решение
- Дата рождения → если < 13 → блок (по аналогии с COPPA).
- Следить за новым законодательством.

## 11. Израиль

### Текущий статус (март 2026)
- Законопроекты **рассматриваются**, но полноценный запрет пока **не принят**.
- Обсуждается ограничение для детей до 14 или 16 лет.
- Предложения включают обязательную верификацию через документы.

### Решение
- Консервативный подход: дата рождения → если < 13 → блок.
- Мониторить законодательные изменения.

## 12. Индия — DPDP Act

### Закон
- **Digital Personal Data Protection Act 2023**.
- Все пользователи до **18 лет** считаются детьми.

### Требования
1. **Верифицированное согласие родителя** для обработки данных любого пользователя < 18.
2. Конкретный метод верификации пока не определён.

### Решение
- Дата рождения → если < 18 → поток согласия родителя.
- Или: установить порог 18+ для Индии (проще).

## 13. Япония

### Текущий статус
- **Нет** специального закона об обязательной верификации возраста для соцсетей.
- Платформы устанавливают порог 13+ по собственной политике.
- Ведутся дискуссии, упор на «интернет-грамотность» в школах.

### Решение
- Дата рождения → если < 13 → блок (по аналогии с мировым стандартом).

## 14. Apple App Store — требования

### Возрастные рейтинги (обновление июль 2025, обязательно до 31 января 2026)
| Рейтинг | Описание |
|---|---|
| 4+ | Без ограничений |
| 9+ | Мягкий контент |
| 12+ | Умеренный контент |
| **13+** | **НОВЫЙ** — добавлен в 2025 |
| **16+** | **НОВЫЙ** — добавлен в 2025 |
| 17+ | Только для взрослых |
| **18+** | **НОВЫЙ** — добавлен в 2025 |

### Что нужно для соцсети
1. **Заполнить новый опросник** в App Store Connect — отвечает за назначение рейтинга:
   - Есть ли в приложении социальное взаимодействие?
   - Есть ли UGC (пользовательский контент)?
   - Какие меры модерации?
2. **Рекомендуемый рейтинг для соцсети**: **12+** или **16+** (в зависимости от контента).
3. Если приложение в категории **Kids** (Дети):
   - Обязательный parental gate (ворота для родителей) перед ссылками, покупками.
   - Нельзя использовать сторонние рекламные SDK (только Families-certified).
   - Только «Sign in with Apple for Kids».
4. Для соцсети с UGC — **не ставить** в категорию Kids, но обеспечить модерацию.
5. **Интегрировать Apple Age Signals** (новое API) в штатах США, где действуют законы о верификации возраста при загрузке.

### Что нельзя
- Использовать данные о возрасте для профилирования, маркетинга.
- Не обновить рейтинг до 31.01.2026 → блокировка обновлений приложения.

## 15. Google Play — требования

### Целевая аудитория (Developer Console)
В Play Console необходимо указать возрастную группу:
- До 5 лет, 6–8, 9–12, 13–15, 16–17, 18+.

### Что нужно для соцсети
1. **Целевая аудитория**: указать **16+** или **18+** (для соцсети без детского контента).
2. Если аудитория включает детей — обязательно соблюдение **Families Policy**:
   - Только Families Self-Certified Ads SDK.
   - Полное соответствие COPPA / GDPR.
   - Нельзя собирать персональные данные детей без VPC.
3. **Новая опция «Restrict Declared Minors»** — позволяет запретить загрузку для несовершеннолетних.
4. **Google Play Age Signals API** (бета) — интегрировать для штатов США с законами о верификации.
5. Для смешанной аудитории — реализовать разные UX для разных возрастных групп.

### Что нельзя
- Заявить аудиторию «все возрасты», если контент не подходит для детей → Google может переназначить и применить санкции.

## 16. Как реализовать — пошаговый план

### Шаг 1: Регистрация (все способы)

```
Пользователь начинает регистрацию
├─ Через Google / Facebook / Apple:
│   └─ Получить профиль → если нет даты рождения → запросить отдельно
└─ Через собственную форму:
    └─ Поля: email, имя, пароль, ДАТА РОЖДЕНИЯ, СТРАНА
```

### Шаг 2: Проверка возраста (на бэкенде)

```
1. Рассчитать полный возраст из даты рождения
2. Определить страну пользователя
3. Найти правила для страны:
   - minAge = минимальный допустимый возраст
   - consentAge = возраст для самостоятельной регистрации
   - hardBan = запрещено ли согласие родителя
4. Решение:
   ├─ возраст >= consentAge → РАЗРЕШИТЬ регистрацию
   ├─ возраст >= minAge И hardBan = false → ЗАПРОСИТЬ согласие родителя
   ├─ возраст >= minAge И hardBan = true → ЗАБЛОКИРОВАТЬ
   └─ возраст < minAge → ЗАБЛОКИРОВАТЬ
```

### Шаг 3: Поток согласия родителя (если требуется)

```
1. Показать экран: «Для регистрации пользователей до [X] лет
   в вашей стране требуется согласие родителя/опекуна»
2. Запросить email родителя
3. Отправить на этот email письмо со ссылкой-подтверждением
4. Родитель переходит по ссылке → подтверждает согласие
5. Только после подтверждения → завершить регистрацию
```

### Шаг 4: Удаление данных

```
1. После расчёта возраста → УДАЛИТЬ сырую дату рождения
2. Сохранить ТОЛЬКО:
   - age_bracket: "under13" | "13-15" | "16-17" | "18+"
   - country: "US" | "DE" | "AU" | ...
   - parental_consent: true/false (если применимо)
   - consent_timestamp: дата подтверждения (если применимо)
```

### Таблица правил по странам (для бэкенда)

```javascript
// Пример конфигурации (не хранит дату рождения!)
const COUNTRY_RULES = {
  // Америка
  US: { minAge: 13, consentAge: 13, hardBan: true },
  CA: { minAge: 13, consentAge: 13, hardBan: true },
  BR: { minAge: 13, consentAge: 16, hardBan: false },
```

## 17. Методы верификации родительского согласия

### Одобренные FTC (COPPA) методы

| Метод | Описание | Когда использовать | Надёжность |
|---|---|---|---|
| **Кредитная карта** | Родитель совершает микротранзакцию (или возвратную транзакцию) | Для любых целей | ★★★★ |
| **Email Plus** | Email + дополнительное подтверждение (повторный email или SMS) | **Только для внутреннего использования данных** (не для передачи третьим лицам) | ★★★ |
| **Knowledge-Based Authentication** | Серия вопросов по кредитной/адресной истории (доступна через сервисы типа LexisNexis) | Для любых целей | ★★★★ |
| **Text-Plus** | SMS + повторный SMS-код | По аналогии с Email Plus | ★★★ |
| **Гос. ID + распознавание лица** | Загрузка паспорта/прав + селфи для сверки | Для максимальной безопасности | ★★★★★ |

### Рекомендация для нашей соцсети

**Минимальный вариант (MVP):**
- Email Plus — родитель получает email со ссылкой, переходит, подтверждает.
- Этого достаточно для COPPA (внутреннее использование) и GDPR.

**Продвинутый вариант (для UK, Австралии, Бразилии):**
- Интеграция с Yoti, OneID или аналогичным провайдером для:
  - Проверки документа (паспорт, ID).
  - Facial age estimation (оценка возраста по лицу).
- Стоимость: обычно $0.05–$0.50 за проверку.

## 18. Какие данные хранить, какие удалять

| Данные | Хранить? | Причина |
|---|---|---|
| Дата рождения (сырая) | **НЕТ — удалить сразу** | COPPA / GDPR — минимизация данных |
| Возрастная группа (`under13`, `13-15`, `16-17`, `18+`) | **ДА** | Необходимо для контроля контента |
| Страна | **ДА** | Необходимо для определения юрисдикции |
| Статус согласия родителя | **ДА** (если применимо) | Юридическое требование |
| Дата и время согласия | **ДА** (если применимо) | Аудиторский след |
| Email родителя | **ДА** (пока активен аккаунт) | Для связи, отзыва согласия |

### Важно
- Дата рождения НЕ должна попадать в логи, аналитику, базу данных.
- Расчёт возраста → запись категории → удаление DOB — всё в одной транзакции.

## 19. Стоит ли давать доступ детям?

### Вариант A: Полный блок до 13 лет (рекомендуется)

**Плюсы:**
- Максимально простая реализация.
- Минимальные юридические риски.
- Не нужно реализовывать VPC, родительский контроль, ограниченный режим.
- Соответствует COPPA, GDPR, большинству законов.

**Минусы:**
- Теряем аудиторию 8–12 лет.
- В Австралии всё равно нужно блокировать до 16.

### Вариант B: Допустить 13–17 с ограничениями

**Плюсы:**
- Расширяет аудиторию.
- Многие соцсети (Instagram, TikTok) работают по этой модели.

**Что нужно реализовать:**
- Поток согласия родителя (Email Plus минимум).
- Ограниченный режим для 13–17: без рекламы, без рекомендаций «для взрослых», усиленная модерация.
- Родительские инструменты: просмотр активности, ограничение времени, управление контактами.
- Для Бразилии (< 16): привязка к аккаунту опекуна + отчёты.
- Для Индии (< 18): согласие родителя для всех.

### Вариант C: Допустить всех (с детским режимом)

**Не рекомендуется** — слишком сложно, слишком много юридических рисков:
- Нужен полный COPPA compliance для < 13.
- Families Policy от Google Play / Apple.
- Отдельная Kids-версия или встроенный Kids Mode.
- Постоянный аудит, отчётность, DPO (Data Protection Officer).

### Наша рекомендация

> **Вариант A (полный блок до 13) + ограниченный режим для 13–17.**
> Это покрывает большинство юрисдикций и обе магазины приложений.
> Для Австралии — порог 16.
> Для Индии — согласие родителя до 18.

## 20. Чек-лист перед запуском

### Регистрация и верификация возраста
- [ ] Добавить поле **даты рождения** при всех способах регистрации
- [ ] Добавить поле **страны** (или определять автоматически по IP + подтверждение)
- [ ] Реализовать расчёт возраста на бэкенде
- [ ] Реализовать таблицу правил по странам (minAge, consentAge, hardBan)
- [ ] Заблокировать регистрацию для пользователей ниже минимального возраста
- [ ] Реализовать поток согласия родителя (Email Plus как минимум)
- [ ] **Удалять дату рождения** сразу после расчёта возраста
- [ ] Хранить только: возрастную группу, страну, статус согласия

### Политики и документы
- [ ] Обновить **Privacy Policy** — описать сбор DOB, его цель, удаление
- [ ] Создать **Children's Privacy Policy** (требование COPPA)
- [ ] Добавить **Terms of Service** — минимальный возраст, ограничения
- [ ] GDPR: подготовить **DPIA** (Data Protection Impact Assessment) для обработки данных детей

### App Store (Apple)
- [ ] Заполнить новый **опросник возрастного рейтинга** в App Store Connect
- [ ] Установить рейтинг **12+** или **16+**
- [ ] **НЕ** ставить в категорию Kids (если это соцсеть для всех)
- [ ] Интегрировать **Apple Age Signals** API (для штатов США)
- [ ] Убедиться, что возрастные/согласительные данные не используются для маркетинга

### Google Play
- [ ] Указать **целевую аудиторию 16+** или **18+** в Play Console
- [ ] Если указано «включая детей» — соблюсти **Families Policy**
- [ ] Рассмотреть опцию **«Restrict Declared Minors»**
- [ ] Интегрировать **Google Play Age Signals API** (бета, для штатов США)
- [ ] Только **Families Self-Certified Ads SDKs** если дети в аудитории

### Техническая безопасность
- [ ] DOB не попадает в логи, аналитику, бэкапы
- [ ] DOB удаляется в той же транзакции, где рассчитывается возраст
- [ ] Данные согласия родителя защищены (шифрование, контроль доступа)
- [ ] Нет профилирования / поведенческой рекламы для пользователей < 18

### Мониторинг законодательства
- [ ] Отслеживать **новый закон Канады** (ожидается ограничение до 14)
- [ ] Отслеживать **закон Израиля** (на рассмотрении)
- [ ] Отслеживать **EU Digital Identity Wallet** (конец 2026)
- [ ] Отслеживать **федеральный закон США** (возможны изменения сверх COPPA)
- [ ] Отслеживать **изменения DSA** (Европарламент голосовал за порог 16)
