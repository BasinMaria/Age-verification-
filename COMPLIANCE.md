## 1. Главный вывод — стратегия 18+ с датой рождения

### Да, подход 18+ с датой рождения — правильный и самый простой

**Если мы ставим приложение 18+ — это СИЛЬНО упрощает жизнь:**
- Не нужно реализовывать родительский контроль.
- Не нужно поток согласия родителя (VPC).
- Не нужно соблюдать Families Policy Google Play / Apple Kids Category.
- Не нужно ограниченный режим для детей.
- Не попадаем под COPPA (мы не «направлены на детей»).

**Простого чекбокса «мне есть 18» — недостаточно.** Большинство законов 2025–2026 года прямо запрещают self-declaration (самодекларацию) как единственный метод проверки возраста.

### Что конкретно делать при регистрации

#### Собственная регистрация (email + имя + пароль)
```
Форма регистрации:
  - Email          ← уже есть
  - Имя            ← уже есть
  - Пароль         ← уже есть
  - Дата рождения  ← ДОБАВИТЬ (день / месяц / год)
```
- Дату рождения → рассчитать возраст → если < 18 → **отказать в регистрации**.
- **Удалить** сырую дату рождения сразу после расчёта → хранить только `age_bracket: "18+"` или `"under18"`.

#### Регистрация через Google / Facebook / Apple

**Да, нужна дополнительная форма для даты рождения.** Вот почему:

| Провайдер | Передаёт дату рождения? | Что делать |
|---|---|---|
| **Google** | Иногда (зависит от scope `profile` + `birthday`) — часто НЕ передаёт | Показать форму «Укажите дату рождения» |
| **Facebook** | Только если пользователь дал разрешение на `user_birthday` — часто НЕ передаёт | Показать форму «Укажите дату рождения» |
| **Apple** | **НЕТ** — Apple Sign-In никогда не передаёт дату рождения | **Всегда** показать форму «Укажите дату рождения» |

**Поток для соцсетей:**
```
1. Пользователь нажимает «Войти через Google / Facebook / Apple»
2. Получаем профиль (email, имя)
3. Проверяем: есть ли дата рождения в ответе?
   ├─ ДА → рассчитать возраст → если >= 18 → пустить
   └─ НЕТ (обычный случай) → показать экран:
       ┌─────────────────────────────────────┐
       │  Для завершения регистрации         │
       │  укажите дату рождения:             │
       │                                     │
       │  [ДД] / [ММ] / [ГГГГ]              │
       │                                     │
       │  Дата используется только для       │
       │  проверки возраста и не сохраняется  │
       │                                     │
       │         [ Продолжить ]              │
       └─────────────────────────────────────┘
4. Рассчитать возраст → если < 18 → отказать
5. Удалить дату рождения, хранить только age_bracket
```

### Почему 18+ проще всего — сводка

| Фактор | С детьми (13+) | Только 18+ |
|---|---|---|
| Родительское согласие | Нужно во многих странах | **Не нужно** |
| COPPA compliance | Нужен если дети из США | **Не нужен** |
| Apple Kids Category | Возможно | **Не нужно** |
| Google Families Policy | Возможно | **Не нужно** |
| Ограниченный режим | Нужен | **Не нужен** |
| Родительский контроль | Нужен | **Не нужен** |
| Рейтинг в магазинах | 12+ / 16+ | **17+ / 18+** |
| Юридическая сложность | Высокая | **Низкая** |

> **Вывод: 18+ — это правильный выбор для MVP.** Просто добавить поле даты рождения везде, включая форму после входа через соцсети.

## 2. Определение страны по геолокации (GeoIP) — вместо вопроса

### Да, можно определять страну по геоданным — и это правильный подход

**Не нужно спрашивать пользователя «В какой вы стране?»** — можно определить автоматически.

### Как это работает

```
Пользователь открывает приложение / сайт
    │
    ▼
Сервер получает IP-адрес пользователя
    │
    ▼
GeoIP-сервис → определяет страну (код: US, DE, AU, IL...)
    │
    ▼
Применяем правила для этой страны
```

### Методы определения страны

| Метод | Точность | Стоимость | Рекомендация |
|---|---|---|---|
| **GeoIP по IP-адресу** (серверный) | ~95–99% на уровне страны | Бесплатно (MaxMind GeoLite2) или $25–100/мес (платные) | ✅ **Рекомендуется как основной** |
| **Browser Geolocation API** (GPS/Wi-Fi) | ~99%+ | Бесплатно | ⚠️ Требует разрешения пользователя; для UK-детей — выключен по умолчанию |
| **Номер телефона** (код страны) | ~90% | Зависит от SMS-провайдера | ⚠️ Не у всех есть номер; дополнительный метод |
| **Язык / часовой пояс браузера** | ~60–70% | Бесплатно | ❌ Ненадёжно как единственный метод |
| **SIM-карта / мобильный оператор** | ~99% | Нужна интеграция с оператором | ⚠️ Только для мобильных; доступно не везде |

### ✅ Рекомендуемый подход: GeoIP + подтверждение

```
1. На сервере: определить страну по IP → GeoIP (MaxMind / ipinfo.io / ip-api)
2. Применить правила для этой страны автоматически
3. НЕ спрашивать пользователя «Где вы?»
4. НО — дать возможность изменить страну вручную
   (на случай VPN, ошибки GeoIP, путешествия)
```

**Почему не только GeoIP:**
- VPN может показать другую страну (~15–25% пользователей используют VPN).
- Прокси, Tor, корпоративные сети могут искажать геолокацию.
- Пользователь может путешествовать (гражданин Австралии в США).

**Рекомендация: при определении страны через GeoIP — применять правила СТРОЖАЙШЕЙ юрисдикции при сомнениях.**

### Юридические требования к использованию GeoIP

| Требование | Закон | Что делать |
|---|---|---|
| IP-адрес = персональные данные | GDPR, UK GDPR | Указать в Privacy Policy что используем IP для определения страны |
| Минимизация данных | GDPR, COPPA | **НЕ хранить** IP-адрес после определения страны; хранить только код страны |
| Прозрачность | GDPR, COPPA, DSA | Объяснить пользователю: «Мы определяем вашу страну для применения возрастных ограничений» |
| Геолокация для детей — выключена по умолчанию | UK Children's Code (Standard 10) | Если пользователь < 18 — НЕ использовать GPS/Browser Geolocation для трекинга |
| Возможность коррекции | GDPR (право на исправление) | Дать пользователю кнопку «Изменить страну» |
| Законная основа | GDPR Art. 6(1)(f) | «Законный интерес» — определение юрисдикции для compliance |

### ⚠️ Важно: GeoIP на сервере ≠ GPS-трекинг

| | GeoIP (серверный) | GPS / Browser Geolocation |
|---|---|---|
| Что определяет | Страна, город (примерно) | Точные координаты (до метров) |
| Нужно разрешение | **НЕТ** | **ДА** (всплывающее окно) |
| Ограничения UK Children's Code | Минимальные | Строгие (выключено по умолчанию для детей) |
| Подходит для определения страны | **ДА** ✅ | Избыточно, не нужно |
| Хранение | Не хранить IP; хранить только код страны | **НЕ хранить** координаты |

### Конкретные GeoIP-сервисы

| Сервис | Цена | Точность (страна) | Примечание |
|---|---|---|---|
| **MaxMind GeoLite2** | Бесплатно | ~99% | Самостоятельный хостинг (база данных); обновлять раз в неделю |
| **MaxMind GeoIP2** | от $25/мес | ~99.8% | Платная версия, выше точность |
| **ipinfo.io** | Бесплатно до 50K запросов/мес | ~99% | REST API; просто интегрировать |
| **ip-api.com** | Бесплатно (некоммерческое) | ~98% | Для коммерческого — $15/мес |
| **Cloudflare** | Бесплатно (если используете CF) | ~99% | Заголовок `CF-IPCountry` — страна уже определена |

> **Самый простой вариант:** если используете Cloudflare — страна приходит бесплатно в заголовке каждого запроса. Не нужно ничего дополнительно интегрировать.

### 🟢 ЗЕЛЁНАЯ ГРУППА — Достаточно только DOB

**Страны: США, Канада, Япония, Израиль, большинство стран мира без специальных законов**

**Что делать:**
1. Добавить поле даты рождения (всегда, включая вход через соцсети).
2. Рассчитать возраст → если < 18 → отказать.
3. Удалить DOB сразу после расчёта.
4. В Privacy Policy написать: «Мы собираем дату рождения исключительно для проверки возраста. Дата удаляется сразу после проверки и не хранится.»
5. Всё. Больше ничего не нужно.

---

### 🟡 ЖЁЛТАЯ ГРУППА — DOB + документация / политики

**Страны: ЕС (все 27 стран), Бразилия, Индия**

**Что делать (помимо DOB):**

1. **Privacy Policy** — должна быть:
   - На языке пользователя (минимум: английский + язык страны).
   - Содержать раздел о детях / возрастной проверке.
   - Указывать правовое основание обработки (GDPR Art. 6(1)(b) — исполнение договора, или Art. 6(1)(f) — законный интерес).
   - Описывать какие данные собираются, зачем, как долго хранятся.

2. **Уведомление DPA** (Data Protection Authority) — в некоторых странах ЕС может потребоваться уведомление регулятора о обработке данных.

3. **Назначить представителя в ЕС** (если нет офиса в ЕС) — требование GDPR Art. 27.

4. **DPIA** (Data Protection Impact Assessment) — оценка воздействия на защиту данных, рекомендуется при обработке данных несовершеннолетних (даже если блокируем < 18, данные кратковременно обрабатываются).

5. **Для Бразилии дополнительно:** Digital ECA запрещает самодекларацию — рассмотреть усиление (двойная проверка: DOB + один дополнительный сигнал, например, кредитная карта).

6. **Для Индии дополнительно:** DPDP Act определит конкретный метод верификации — следить за обновлениями.

---

### 🔴 КРАСНАЯ ГРУППА — DOB недостаточно, нужна доп. верификация

**Страны: Великобритания, Австралия, Китай, Южная Корея, Малайзия**

#### Великобритания 🇬🇧

**Проблема:** Ofcom прямо говорит что ввод даты рождения (self-declaration) — **НЕ является «высокоэффективной»** проверкой возраста.

**Что делать:**
1. DOB как первый шаг (начальный фильтр).
2. **Плюс один из методов:**
   - Интеграция с **Yoti** (facial age estimation) — ~$0.10–0.50 за проверку.
   - Интеграция с **OneID** (Open Banking verification) — подтверждает возраст через банк.
   - Проверка **кредитной карты** — микротранзакция для подтверждения что карта «взрослая».
   - Проверка через **мобильного оператора** (Vodafone / O2 / Three / EE предоставляют Age Verification API).
3. **Ежегодная оценка рисков для детей** (Children's Risk Assessment) — документ описывающий риски и меры.

**Стоимость:** $0.10–0.50 за верификацию.
**Провайдеры:** Yoti (https://yoti.com), OneID (https://oneid.uk), AgeChecked (https://agechecked.com).

#### Австралия 🇦🇺

**Проблема:** Закон запрещает ЛЮБОЙ доступ к соцсетям для < 16, даже с согласием родителей. Self-declaration недостаточна.

**Что делать:**
1. DOB как первый шаг.
2. **Плюс:** интеграция со сторонним сервисом верификации:
   - **Biometric age estimation** (оценка возраста по лицу) — Yoti, Persona.
   - **eKYC** (electronic Know Your Customer) — проверка по документу.
3. Если пользователь из Австралии и < 16 → **полный блок без вариантов**.

**Провайдеры:** Persona (https://withpersona.com), Yoti, IDnow.

#### Китай 🇨🇳

**Проблема:** Обязательная регистрация по реальному имени. Без национального ID — нельзя.

**Что делать:**
- Если планируете работать в Китае:
  1. Найти **китайского партнёра** для верификации (через национальный ID-систему).
  2. Интегрировать **реальноимённую регистрацию**.
  3. Соблюдать правила по ограничению времени для несовершеннолетних.
- **Или:** не запускаться в Китае на первом этапе (проще).

#### Южная Корея 🇰🇷

**Проблема:** Требуется верификация через государственную систему.

**Что делать:**
- Интеграция с **i-PIN** (виртуальный идентификатор) или верификация через мобильный номер (привязан к реальному имени).
- **Или:** не запускаться в Южной Корее на первом этапе.

#### Малайзия 🇲🇾

**Проблема:** С 2026 — обязательная eKYC для соцсетей.

**Что делать:**
- Интеграция с eKYC-провайдером для малайзийских пользователей.
- **Или:** отложить запуск в Малайзии.

### Приоритеты запуска

```
ФАЗА 1 (MVP — запуск):
  ✅ DOB для всех пользователей
  ✅ GeoIP для определения страны
  ✅ Блок всех < 18
  ✅ Privacy Policy (EN + основные языки)
  → Покрывает: США, Канада, Япония, Израиль, ЕС (базово), Индия

ФАЗА 2 (через 1–3 месяца):
  ⚠️ Enhanced verification для UK (Yoti / OneID)
  ⚠️ Enhanced verification для Австралии (biometric / eKYC)
  ⚠️ Privacy Policy на всех языках ЕС
  ⚠️ DPIA документ для ЕС
  → Покрывает: Великобританию, Австралию, Бразилию

ФАЗА 3 (позже):
  🔴 Китай — реальноимённая регистрация (если нужен этот рынок)
```

## 5. США — COPPA

### Закон
- **Children's Online Privacy Protection Act**, 16 CFR Part 312.
- Крупное обновление вступает в силу **22 апреля 2026**.
- Распространяется на сайты/приложения, направленные на детей до 13 лет **ИЛИ** имеющие фактическое знание о пользователях до 13 лет.

### Что можно
- Собирать дату рождения **только для проверки возраста** без согласия родителя, при условии:
  - Данные используются **только** для определения возраста.
  - Данные **удаляются сразу** после проверки.
  - Данные **не передаются** третьим лицам.

### Что нельзя (если пользователь < 13)
- Собирать **любые персональные данные** без верифицированного согласия родителя (VPC).
- Использовать данные детей для профилирования, рекламы, трекинга.
- Хранить данные дольше, чем необходимо.
- С 2026: передавать данные детей третьим лицам без **отдельного** согласия.

### Штрафы
| Нарушение | Штраф |
|---|---|
| Каждое нарушение (за ребёнка, за день) | **до $53 088** |
| Пример: 1000 детей × 30 дней | **~$1.6 миллиарда** |

### Решение для нашей соцсети
- При регистрации: собрать дату рождения → рассчитать возраст.
- Если < 13 → **отказать в регистрации** (самый простой и безопасный путь).
- Удалить дату рождения сразу после расчёта.
- Если в будущем захотим допустить детей — реализовать полный VPC-поток (см. раздел 17).

## 6. ЕС — GDPR + Digital Services Act

### Закон
- **GDPR Article 8**: по умолчанию возраст цифрового согласия = 16, но страны-участники могут снизить до 13.
- **Digital Services Act (DSA) Article 28**: платформы обязаны принимать «соразмерные» меры для защиты несовершеннолетних; таргетированная реклама для детей запрещена.
- **Европарламент (ноябрь 2025)**: голосование за единый порог 16 лет для соцсетей без согласия родителя.

### Что нужно сделать
1. Собирать дату рождения + страну при регистрации.
2. Определить национальный порог (см. таблицу выше).
3. Если возраст < порога → потребовать согласие родителя **ИЛИ** заблокировать.
4. Данные для проверки возраста минимизировать и не перепрофилировать.

### Штрафы
| Нарушение | Штраф |
|---|---|
| GDPR | **до €20 млн или 4% мирового оборота** (что больше) |
| DSA | **до 6% мирового оборота** |

### Решение
- Дата рождения + страна → определение возрастной группы → хранить только группу.
- Для пользователей между `minAge` и `consentAge` → поток согласия родителя (email-подтверждение).
- Для пользователей < 13 → блок.

## 7. Великобритания — Online Safety Act

### Закон
- **Online Safety Act 2023**, применяется с июля 2025.
- Регулятор: **Ofcom**.
- Возраст цифрового согласия: **13** (UK GDPR).

### Ключевые требования
1. **«Высокоэффективная» проверка возраста** — простая самодекларация (ввести дату, поставить галочку) **НЕ достаточна** по рекомендациям Ofcom.
2. **Допустимые методы**: проверка по документу (паспорт), оценка возраста по лицу, Open Banking, проверка через мобильного оператора, кредитная карта, цифровая идентификация.
3. **Недопустимые методы**: самодекларация, дебетовая карта без проверки возраста, просто предупреждение.
4. Ежегодная **оценка рисков для детей** — обязательна.

### Штрафы
| Нарушение | Штраф |
|---|---|
| Несоблюдение требований Ofcom | **до 10% мирового дохода** или блокировка сервиса |

### Решение
- Дата рождения как начальный гейт.
- Для пользователей из UK: **дополнительно** интегрировать стороннего провайдера верификации (Yoti, OneID, AgeChecked) для enhanced verification.
- Или: проверка через мобильного оператора (Vodafone/O2/Three/EE Age Verification API).

## 8. Австралия — запрет до 16 лет

### Закон
- **Online Safety Amendment (Social Media Minimum Age) Act 2024**.
- Действует с **10 декабря 2025**.
- **Жёсткий запрет** на соцсети для лиц до 16 лет. Родители **НЕ могут** дать согласие.

### Ключевые требования
1. Платформа должна принять «разумные меры» для предотвращения доступа лиц до 16.
2. Простая самодекларация — **недостаточна**.
3. Допустимые методы: проверка документа, биометрическая оценка возраста.

### Штрафы
| Нарушение | Штраф |
|---|---|
| Невыполнение требований | **до AUD $49.5 миллионов** (~$32 млн USD) |

### Решение
- Для австралийских пользователей: дата рождения → если < 16 → **полный блок, без вариантов**.
- Рассмотреть интеграцию со сторонним сервисом оценки возраста (facial age estimation).
- Никакого потока «согласие родителя» — закон его не допускает.

- Для китайских пользователей: верификация через национальный ID (или делегировать партнёру).

- 14–18 → ограниченный режим.

## 18. Как реализовать — пошаговый план

### Шаг 1: Регистрация (все способы)

```
Пользователь начинает регистрацию
├─ Через Google / Facebook / Apple:
│   └─ Получить профиль → если нет даты рождения → показать форму DOB
└─ Через собственную форму:
    └─ Поля: email, имя, пароль, ДАТА РОЖДЕНИЯ
    └─ (страну НЕ спрашиваем — определяем по GeoIP автоматически)
```

### Шаг 2: Определение страны (на бэкенде, автоматически)

```
1. Получить IP-адрес пользователя из HTTP-запроса
2. Определить страну через GeoIP (MaxMind / Cloudflare / ipinfo.io)
3. Сохранить код страны (US, DE, AU...) — НЕ сохранять IP
4. Если GeoIP не смог определить → применить строгие правила (OTHER)
```

### Шаг 3: Проверка возраста (на бэкенде)

```
1. Рассчитать полный возраст из даты рождения
2. Взять код страны из Шага 2
3. Найти правила для страны:
   - minAge = минимальный допустимый возраст (для 18+ стратегии: всегда 18)
   - needsEnhancedVerification = нужна ли доп. проверка (UK, AU...)
4. Решение:
   ├─ возраст >= 18 → РАЗРЕШИТЬ регистрацию
   └─ возраст < 18 → ЗАБЛОКИРОВАТЬ (показать сообщение)
5. Дополнительно (Фаза 2):
   ├─ страна = GB, AU → запросить enhanced verification (Yoti / eKYC)
   └─ страна = CN, KR → запросить ID-верификацию
```

### Шаг 4: Удаление данных

```
1. После расчёта возраста → УДАЛИТЬ сырую дату рождения
2. Сохранить ТОЛЬКО:
   - age_bracket: "18+" или "under18"
   - country: "US" | "DE" | "AU" | ... (определена по GeoIP)
3. НЕ сохранять:
   - Дату рождения
   - IP-адрес
```

## 19. Методы верификации родительского согласия

### Одобренные FTC (COPPA) методы

| Метод | Описание | Когда использовать | Надёжность |
|---|---|---|---|
| **Кредитная карта** | Родитель совершает микротранзакцию (или возвратную транзакцию) | Для любых целей | ★★★★ |
| **Email Plus** | Email + дополнительное подтверждение (повторный email или SMS) | **Только для внутреннего использования данных** (не для передачи третьим лицам) | ★★★ |
| **Knowledge-Based Authentication** | Серия вопросов по кредитной/адресной истории (доступна через сервисы типа LexisNexis) | Для любых целей | ★★★★ |
| **Text-Plus** | SMS + повторный SMS-код | По аналогии с Email Plus | ★★★ |
| **Гос. ID + распознавание лица** | Загрузка паспорта/прав + селфи для сверки | Для максимальной безопасности | ★★★★★ |

### Рекомендация для нашей соцсети

**Минимальный вариант (MVP):**
- Email Plus — родитель получает email со ссылкой, переходит, подтверждает.
- Этого достаточно для COPPA (внутреннее использование) и GDPR.

**Продвинутый вариант (для UK, Австралии, Бразилии):**
- Интеграция с Yoti, OneID или аналогичным провайдером для:
  - Проверки документа (паспорт, ID).
  - Facial age estimation (оценка возраста по лицу).
- Стоимость: обычно $0.05–$0.50 за проверку.

## 20. Какие данные хранить, какие удалять

| Данные | Хранить? | Причина |
|---|---|---|
| Дата рождения (сырая) | **НЕТ — удалить сразу** | COPPA / GDPR — минимизация данных |
| Возрастная группа (`under13`, `13-15`, `16-17`, `18+`) | **ДА** | Необходимо для контроля контента |
| Страна | **ДА** | Необходимо для определения юрисдикции |
| Статус согласия родителя | **ДА** (если применимо) | Юридическое требование |
| Дата и время согласия | **ДА** (если применимо) | Аудиторский след |
| Email родителя | **ДА** (пока активен аккаунт) | Для связи, отзыва согласия |

### Важно
- Дата рождения НЕ должна попадать в логи, аналитику, базу данных.
- Расчёт возраста → запись категории → удаление DOB — всё в одной транзакции.

## 21. Стоит ли давать доступ детям?

### Вариант A: Полный блок до 13 лет (рекомендуется)

**Плюсы:**
- Максимально простая реализация.
- Минимальные юридические риски.
- Не нужно реализовывать VPC, родительский контроль, ограниченный режим.
- Соответствует COPPA, GDPR, большинству законов.

**Минусы:**
- Теряем аудиторию 8–12 лет.
- В Австралии всё равно нужно блокировать до 16.

### Вариант B: Допустить 13–17 с ограничениями

**Плюсы:**
- Расширяет аудиторию.
- Многие соцсети (Instagram, TikTok) работают по этой модели.

**Что нужно реализовать:**
- Поток согласия родителя (Email Plus минимум).
- Ограниченный режим для 13–17: без рекламы, без рекомендаций «для взрослых», усиленная модерация.
- Родительские инструменты: просмотр активности, ограничение времени, управление контактами.
- Для Бразилии (< 16): привязка к аккаунту опекуна + отчёты.
- Для Индии (< 18): согласие родителя для всех.

### Вариант C: Допустить всех (с детским режимом)

**Не рекомендуется** — слишком сложно, слишком много юридических рисков:
- Нужен полный COPPA compliance для < 13.
- Families Policy от Google Play / Apple.
- Отдельная Kids-версия или встроенный Kids Mode.
- Постоянный аудит, отчётность, DPO (Data Protection Officer).

### Наша рекомендация

> **Вариант A (полный блок до 13) + ограниченный режим для 13–17.**
> Это покрывает большинство юрисдикций и обе магазины приложений.
> Для Австралии — порог 16.
> Для Индии — согласие родителя до 18.

## 22. Чек-лист перед запуском

### ФАЗА 1 — MVP (стратегия 18+)

#### Регистрация и верификация возраста
- [ ] Добавить поле **даты рождения** в собственную форму регистрации (email + имя + пароль + **DOB**)
- [ ] Добавить **экран ввода DOB** после входа через Google / Facebook / Apple (если DOB не пришёл от провайдера)
- [ ] Реализовать **GeoIP** на бэкенде для автоматического определения страны (MaxMind GeoLite2 / Cloudflare)
- [ ] Реализовать расчёт возраста → если < 18 → **блокировать регистрацию**
- [ ] **Удалять дату рождения** сразу после расчёта возраста (в той же транзакции)
- [ ] Хранить только: `age_bracket` ("18+" / "under18") + `country` (код страны из GeoIP)
- [ ] **НЕ** хранить IP-адрес после определения страны

#### Политики и документы
- [ ] Обновить **Privacy Policy** — описать: сбор DOB (цель: проверка возраста, удаление сразу), использование GeoIP (цель: определение юрисдикции)
- [ ] Добавить **Terms of Service** — минимальный возраст 18+
- [ ] Для ЕС: подготовить **DPIA** (Data Protection Impact Assessment)
- [ ] Для ЕС: назначить **представителя** в ЕС (GDPR Art. 27) если нет офиса

#### App Store (Apple)
- [ ] Заполнить новый **опросник возрастного рейтинга** в App Store Connect
- [ ] Установить рейтинг **17+** или **18+** (для 18+ соцсети)
- [ ] **НЕ** ставить в категорию Kids
- [ ] Интегрировать **Apple Age Signals** API (для штатов США)

#### Google Play
- [ ] Указать **целевую аудиторию 18+** в Play Console
- [ ] Включить опцию **«Restrict Declared Minors»**
- [ ] Интегрировать **Google Play Age Signals API** (для штатов США)

#### Техническая безопасность
- [ ] DOB не попадает в логи, аналитику, бэкапы
- [ ] DOB удаляется в той же транзакции, где рассчитывается возраст
- [ ] IP-адрес не хранится после GeoIP-определения
- [ ] Нет профилирования / поведенческой рекламы для пользователей

### ФАЗА 2 — Enhanced verification (UK, Австралия)

- [ ] Интегрировать **Yoti** или **OneID** для пользователей из UK (enhanced age assurance)
- [ ] Интегрировать **biometric / eKYC** для пользователей из Австралии
- [ ] Подготовить **Children's Risk Assessment** для UK (требование Ofcom)
- [ ] Privacy Policy на основных языках ЕС (минимум: DE, FR, ES, IT, PT)

### ФАЗА 3 — Специальные рынки

- [ ] Китай: интеграция с реальноимённой регистрацией (через партнёра)
- [ ] Южная Корея: i-PIN / мобильная верификация
- [ ] Малайзия: eKYC-провайдер

### Мониторинг законодательства
- [ ] Отслеживать **новый закон Канады** (ожидается ограничение до 14)
- [ ] Отслеживать **закон Израиля** (на рассмотрении)
- [ ] Отслеживать **EU Digital Identity Wallet** (конец 2026)
- [ ] Отслеживать **федеральный закон США** (возможны изменения сверх COPPA)
- [ ] Отслеживать **изменения DSA** (Европарламент голосовал за порог 16)
